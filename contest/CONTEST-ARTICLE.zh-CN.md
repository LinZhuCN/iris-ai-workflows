## 在不改变业务流程的前提下监控数据交换

医疗机构会与研究中心、治疗诊所及其他合作方交换数据。每个接收方所需的信息取决于其角色、交换目的和适用要求。审查这些交换，需要把技术消息记录与通常由其他系统维护的业务背景联系起来。

本项目提供**对机构间数据交换进行非侵入式监控，以发现潜在隐私与合规风险**。它在现有 IRIS Interoperability Production 旁采集证据，并使用 IRIS AI Hub Agent 辅助审核。观测路径不要求修改业务 BP，也不会阻断其传送。

例如，某医院将研究数据导出配置为采用 Safe Harbor 去标识化。研究接收方预期收到出生年份和状态信息，但观测到的输出却包含姓名、病历号和完整出生日期。审核人员需要看到这些字段出现在哪条消息中、适用了哪个机构档案，以及为什么所选披露条件值得进一步调查。

应用将这些证据汇集到一起：来源方和接收方、声明的用途、观测到的字段清单、相关 HIPAA 来源段落，以及可供检查的 AI 评估。工作人员可以据此调查数据交换；它不是自动法律判定。

## 本文所说的非侵入式监控

主要场景使用独立观测工作进程，在业务 Production 运行期间采集受支持消息的证据。审核者不会被插入业务 Production 的 BS/BP/BO 传送路径。该路径不会改写路由、修改载荷或自动重发消息。

采集与 AI 审核是分开的操作。在引导式演示中，用户先发送消息、检查采集到的证据，然后授权一项有范围限制的审计。**这是发送后的建议性审核，不是同步筛查，也不承诺实时检测。**发现不能阻止或撤销已经完成的传送。

非侵入式也不意味着无需访问权限或没有开销。观测需要配置消息记录访问权限，本地检查需要明确授权，模型执行还会消耗单独授权的预算。该演示不构成生产性能或延迟保证。

## 演示流程：纳管 Production 并审核研究数据导出

主要演示从固定的 `M5OBSERVATION / Contest.M5.Production` 开始。其底层业务流事先已安装；演示者无需在演示期间构建集成。

用户将：

1. 填写来源医院与研究接收方的说明。
2. 保存双方职责、预期用途、允许／禁止的字段以及接收要求。
3. 纳管 Production 以进行观测，并授权本地合成字段检查。
4. 通过实际 BS/BP/BO 链路和 SQL 接收器发送固定的合成研究消息。
5. 检查新采集的消息证据。
6. 明确授权一次有范围限制的 AI 审计，并查看识别出的问题、支持证据及仍需补充的信息。

“填入示例”只会填充可编辑表单。保存会创建一个有版本的场景前提，并不构成法律批准。发送会冻结当时准确的机构档案，因此后续编辑不会改写该消息所用的上下文。

固定的主机到机构映射是此模拟的明确组成部分。Business Partner key 可以帮助将技术主机与机构关联起来，但仅凭名称无法证明该机构的职责或其接收数据的许可。保存档案不会静默地重新配置 Business Host。

## 从运行时活动到模型可见证据

```text
版本化机构档案
             |
实际 BS -> BP -> BO -> SQL 接收／回读
             |
Production 观测器：header、session、受支持的结构化字段事实
             |
准确的配置 + session + Agent + 费用授权
             |
AI Hub locator -> IRIS 准备来源证据 -> AI Hub judge
             |
IRIS schema / 绑定 / 引文检查
             |
已保存的评估 + 原始响应 + 人工审核
```

监控纳管、消息检查与模型费用刻意分开。纳管 Production 不会自动授权读取消息正文或购买推理服务。

对于受支持的消息，本地检查会提取字段路径是否存在、日期是仅含年份还是完整日期等事实。模型请求包不需要患者标识符的值。不支持的格式和检查失败会明确显示，而不会被当成空的“安全”结果。这是范围有限的结构化检查，不是对自由文本 PHI 的全面检测。

审核分为两个受约束的模型阶段。locator 用于识别相关问题。两个阶段之间由 IRIS 准备来源证据；judge 评估事实并返回结构化问题和引文。这些审核任务没有不受限制的运行时 ToolSet。IRIS 会检查证据引用以及来源原文的准确引述，再接受报告。

检查引文是否存在很有用，但不能证明法律解释正确。因此，界面保留不确定性，并使用“所检查问题未发现信号”，而不是“HIPAA 认证”。

### 代码在哪里运行，以及 Agent 可以作出什么判断

固定的 M5 审核器运行于独立的后台观测工作进程，并绑定到真实业务 Production 的证据。它没有插入该业务 BP。

Agent 会将受支持的观测评估为有范围的风险、需要补充信息，或所检查问题未发现信号。IRIS 验证结果及引文、保存报告，并将后续工作留给人工处理。

仓库还包含两个不同的 Interoperability 决策示例：

| 路径 | AI Hub 决策 | IRIS 执行边界 |
|---|---|---|
| 可选的多机构审计 BP | 在分发完成后评估已转换的接收方输出 | `AdvisoryAudit` 调用审核器并记录建议性报告；不会阻断已完成的分发 |
| 有界消息分诊 BP | 提议 `deliver`、`quarantine` 或 `human_review` | BP 会在 BO 持久化允许的结果之前检查动作和确定性安全条件 |

这些都是真正执行的 `%AI.Agent`，不是换名包装成 AI Hub 的 Python 模型调用。在分诊中，Agent 必须针对 BP 当前案例调用已注册的只读事实 ToolSet。跨案例访问、未使用工具以及不支持的动作都会被拒绝。Agent 没有任意管理 Production 的能力。

采取动作的分诊路径与非侵入式监控场景相互独立；纳管 Production 不会为其传送流程增加分诊关卡。这些区别也说明了应用如何满足[竞赛的 AI Hub 决策任务](https://community.intersystems.com/post/intersystems-programming-contest-ai-agents-interoperability-workflows)。

## 审核面向不同接收方角色的数据交换

可选的多机构演示读取一个版本化的 FHIR Patient，并向三个模拟机构分发实际转换后的输出：

| 接收方 | 协议与隔离 namespace | 有范围的问题 |
|---|---|---|
| 内部质量部门 | SQL / `DEMOQUALITY` | 输出是否符合配置的内部用途／最小化背景？ |
| 外部研究中心 | REST / `DEMORESEARCH` | 实际标识符是否与声明的 Safe Harbor 路径矛盾？ |
| 治疗诊所 | 基于 MLLP 的 HL7 V2 / `DEMOCLINIC` | 对同一患者的一般治疗适用哪些许可和例外？ |

每个分支都有真实接收端证据，而不只是建议的映射。已保存的通过审核发现了研究分支的矛盾，同时对质量和治疗分支给出了范围限定的“未发现信号”。诊所是重要对照：当适用的治疗背景不同时，出现身份信息不自动代表违规。

这些接收端位于同一个本地 IRIS 实例中的不同 namespace／数据库。它们并非独立医院或远程生产系统。在对比版本中删除选定字段，不足以证明完整的 Safe Harbor 去标识化。

## 检查评估结果及其底层模型执行

审核者需要检查评估是如何产生的，而不应只阅读结论。现在每个模型执行操作旁边都有 **AI log** 控件。对于分阶段审计，它会显示：

- 已保留的 locator 和 judge 响应。
- 模型身份、AI Hub sessions 和执行状态。
- 记录的用量及错误。
- 可展开查看的请求输入和系统提示。
- 可供进一步调查的原始存储记录。

打开日志不会发起模型请求或重试。只保存了验证后结果的旧记录，不会被重新标记为提供方原始响应。同样，session ID 或预留请求本身也不会被当作推理成功的证明。

演示始终明确区分接收回执、已捕获的监控证据和已完成的 AI 评估。这是三个不同事件。

## 我们测量了什么，以及没有测量什么

这些运行使用的已配置模型标识符为 `deepseek-flash`。

| 已保存的执行 | 模型请求数 | SDK prompt tokens | SDK completion tokens | SDK 总计 |
|---|---:|---:|---:|---:|
| 固定 M5 入门审计 | 2 | 28,912 | 14,714 | 43,626 |
| 已接受的三接收方审计 | 6 | 70,768 | 26,301 | 97,069 |

M5 运行保留了 AI Hub sessions **226–227**；三接收方运行保留了 sessions **219–224** 和审计 BP session **59**。这些是本地验收标识符，新安装不会重现这些 ID。

多机构表格仅描述已接受的运行。更早的一次六请求尝试（包括研究服务提供方超时）仍有记录；成功运行使用了单独授权的预算。这不是免费或隐藏的自动重试。

如果提供方报告了推理／缓存计数，它们是 completion／prompt 计数的子集，不应重复相加。我们尚未将这些计数与提供方发票核对，因此不声称具体货币成本。两阶段审核对每项选定审核最多预留两次模型请求；该上限不是固定美元成本或 token 单价保证。

这些运行证明运行时和证据路径确实执行过。它们不是具有代表性的临床基准，也不是经过法律验证的准确度分数。

## 使用 AI Hub 和 Agentic Dev 构建时的经验

**让 IRIS 作最终判断。**在分诊中，即便模型回答看似有效，如果要求发送不完整数据或使用未知动作，仍必须失败。在审核中，格式错误的输出、缺少证据或无效引文都不能成为替代性的成功结果。

**明确说明上下文。**在较早的一次治疗测试中，模型询问技术主机与所述诊所及患者活动之间的关系。增加明确映射和数据范围输入，比强迫模型回答“无风险”更合适。原始的未解决报告予以保留。

**将失败和费用视为持久状态。**超时可能消耗预留预算。刷新页面、重新提交相同运行或重启容器，都不得静默购买另一次尝试或重发消息。

**使用开发工具，但不要将它们与运行时 Agent 混为一谈。**我们使用了 [IRIS Agentic Dev](https://github.com/intersystems-community/iris-agentic-dev)，并调整了 Interop Skills，通过固定的 TRIAGE 连接执行类检查、编译、框架测试和诊断。这些 MCP 工具帮助构建应用；它们不是业务 Agent，也不是 Agent 可用的不受限制 ToolSet。

**演练时保留证据。**M5 重置会归档其逻辑纳管、档案和审核工作区。它会保留原始 IRIS 消息、SQL 回执和受保护的模型报告，并让其他 Productions 保持不变。下一次演示可以从干净状态开始，而无需改写此前结果。

## 试用工作流

已测试平台为 ARM64 IRIS for Health AI Hub EAP `2026.3.0AI.154.0`，并使用 Docker Compose、Python 和本地 Web UI。请另行取得获授权的 EAP 镜像和相应许可证；本文不再分发这些内容。当前竞赛公告指定 AI Hub Community build 154。不要替换成普通非 AI Hub 镜像，也不要假定较新的 EAP build 兼容。

请参阅[安装指南](./README.md)、[Web 设置](../web/README.md)和[固定入门演示](./M5-ONBOARDING-DEMO.md)。基础 mock 分诊快速入门并非一次命令即可安装所有扩展监控演示。M5 演示指南说明了额外前提。

配置完成后，现场 M5 演示使用 `/demo/m5`。只读验收检查与范围受限的重置是两项独立操作：

```sh
python3 contest/m5_demo.py --check
python3 contest/m5_demo.py --reset
```

`--check` 需要已保存的本地验收 journal；在全新 clone 上不会伪造该 journal。重置是明确改变状态的演练操作，并非只读检查的一部分。

发布知识包包含约 23 MB 带来源信息的完整准备文本，以及单独标识的 LLM 导读摘要和合成政策。整个包并非全部由 LLM 改写，摘要也不是官方法律文本。历史／未审核资料已从默认检索导出中排除。语料核验不代表已完成导入，也不代表 Agent 准确度评估。

## 此分支新增的内容

本项目源自 [DataPipelineDemo](https://github.com/zlnick/DataPipelineDemo) 的分支；该项目聚焦于 AI 辅助集成分析与管道生成。本作品新增了 ObjectScript AI Hub 运行时决策、确定性执行边界、Production 观测、版本化机构上下文、基于证据的审核和可检查的模型日志。

当前分发版本不再包含继承而来的管道生成应用。我们对原项目予以致谢，而不将其冒充为新作品；上游和 UI／skills 声明保留在 [NOTICE](../NOTICE) 中。

## 边界与后续步骤

这是一个开源合成数据演示，不是可直接用于生产的合规服务。它不能确立真实机构权限，不能检查所有可能的载荷，不能验证接收方后续行为，不能证明法律适用性，也不提供不受限制的自动修复能力。对于作者自定的测试预期，也没有独立法律验证。

有价值的后续工作包括：在干净机器上演练发布、录制简短公开演示视频、由独立人员审核评估标准，以及构建具备适当范围权限的真实场景上下文／格式适配器。

演示工作流让用户纳管现有 Production、从新交换中采集证据，并审核潜在隐私风险，同时不改变该 Production 的传送逻辑。最终报告将发现关联到消息、机构背景、来源段落和模型输出，供人工调查所需。
