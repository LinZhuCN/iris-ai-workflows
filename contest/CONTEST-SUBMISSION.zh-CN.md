## 申请名称

**IRIS AI Hub Interoperability Workflows**

## 简短说明

利用 AI Hub、机构背景和可检查的消息证据，对 IRIS 数据交换进行非侵入式监控，以发现潜在隐私与合规风险，同时不改变被观测的业务流程。

## Open Exchange 描述

在不改变被观测 Production 的业务逻辑或阻断其传送的情况下，监控机构间数据交换，以发现潜在隐私与合规风险。独立观测工作进程将 IRIS 消息证据与版本化机构档案、声明的用途和 IRIS AI Hub Agent 联系起来，支持人工审核。

引导式演示从干净的逻辑工作区开始：填写来源方／接收方档案、纳管固定 Production、授权本地检查、触发合成 BS/BP/BO 数据流，并明确为审计授权预算。IRIS 会记录实际消息／session、SQL 回读及最小化字段事实。Agent 检查所选披露条件和来源证据；IRIS 验证结构化结果与引文。执行按钮旁的 **AI log** 会展示保留的响应、sessions、用量和错误，不会再次调用模型。

业务流程运行期间，监控会采集证据；引导式审计则在传送之后审核这些证据。它不是同步筛查，不保证实时检测，也不会自动进行法律认证。观测需要配置访问权限和检查授权；模型费用另行授权。

主要审核路径与其他工作流示例各有不同作用：

- **建议性审核：**对独立监控的消息作出范围明确的风险、需要补充信息或未发现信号的评估。可选的 FHIR 分发场景也通过审计 BP 执行审核，并将实际 SQL、REST 和 HL7 V2 输出发送到相互隔离的本地接收方 namespace。
- **受控分诊：**另一个独立示例使用绑定到作业的只读事实 ToolSet，提出传送、隔离或人工审核建议。其 Interoperability BP 在 BO 持久化允许的结果前执行确定性策略。监控纳管不会把这条会采取动作的路径安装到被观测的 Production 中。

固定研究示例声明采用 Safe Harbor 去标识化，但实际发送了合成标识符和完整出生日期。机构档案确实参与构成冻结后的模型输入。另一个治疗对照说明，不能脱离业务背景对标识符作分类判断。

模型费用明确且有上限；重试不会自动补充预算。演练重置只归档固定 M5 逻辑工作区，同时保留原始消息和模型报告。应用使用合成数据，不认证 HIPAA 合规，不阻断已完成的披露，也不授权任意修改 Production。

本地测试环境为 ARM64 IRIS for Health AI Hub EAP `2026.3.0AI.154.0`。
请另行获取获授权的 EAP 镜像和相应许可证。安装方式、演示额外前提和已知限制均有文档说明。基础 mock 分诊设置与完整监控演示是不同的设置路径。

## 本项目如何满足竞赛任务

[官方公告](https://community.intersystems.com/post/intersystems-programming-contest-ai-agents-interoperability-workflows)
要求使用 IRIS Interoperability 工作流和 AI Hub Agent 执行决策任务。公告还要求开源发布、提供含安装说明的英文 README、视频**或**工作原理说明，并要求有实质性改进，而不是复制现有应用。

| 要求 | 具体实现／证据 |
|---|---|
| AI Hub 运行时 Agent | `%AI.Agent`、真实模型 sessions 和已保存响应；不是 Python API 包装器 |
| Interoperability 工作流内的决策 | [分诊 BP](./src/Process.cls)：提出动作 → 确定性策略 → BO 持久化 |
| 额外的 AI Hub 审计 BP | [多机构审计 BP](./multiorg/AuditProcess.cls)，与 M5 后台审核器不同 |
| 有用的应用，而非换名分支 | 新的运行时控制、证据采集、档案快照、审核契约、预算核算与 UI |
| 可演示的端到端使用 | [M5 现场入门](./M5-ONBOARDING-DEMO.md)：新档案 → 纳管 → 新消息 → 新审计 |
| 可观测性与成本 | 保留模型输入／输出、sessions、错误和用量；没有账单证据时不声称货币成本 |
| 开发者体验 | 有文档说明的有界演示、测试、明确重置和已知前提；仍需在干净机器上进行发布演练 |

当前公告指定 **AI Hub Community build 154**，不是 162。已测试的 `2026.3.0AI.154.0` ARM64 运行时与该 build 编号一致；发布前应核实实际使用的获许可镜像／发行包。公告明确允许在其所述许可证澄清范围内使用 EAP 进行开发和提交；这并非镜像或许可证的通用再分发授权。

提交期：**2026 年 10 月 26 日至 11 月 8 日**，于 11 月 8 日 23:59 EST 截止；投票于 11 月 9–15 日进行。发布前请重新查看[竞赛页面](https://openexchange.intersystems.com/contest/49)。不要把组织方标注的 EST 擅自换算成假定的本地截止时间。

## 发布前事项

### 录制和截图计划

请从真实运行中采集以下画面；这是一份镜头清单，不表示媒体已经存在。

| 画面 | 评审者应理解的内容 |
|---|---|
| 可编辑的来源方／接收方档案，然后纳管 | 用户提供业务背景，并选择真实 Production |
| 新接收回执与已采集证据并列 | 现有业务流正常运行，同时观测器为审核采集事实 |
| 带准确引文的研究结果 | 发现针对实际声明的披露路径，而非虚构的笼统规则 |
| 显示两个阶段与 session ID 的 AI log | 模型确实执行过；原始输出、失败状态和用量均可检查 |
| 分诊策略／审计轨迹，或可选 `AdvisoryAudit` BP 轨迹 | AI Hub 参与所需的 Interoperability 决策工作流，而不只是独立仪表板 |
