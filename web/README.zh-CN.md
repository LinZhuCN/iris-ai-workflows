## 范围

### M5 固定入门演示

从侧栏、`/demo` 或 Productions 打开 **M5 onboarding**（`/demo/m5`）。
固定入门路由仅限 `M5OBSERVATION / Contest.M5.Production`：

1. 输入并保存源医院和研究接收方资料。**Fill example**（填入示例）只会更改
   可编辑草稿。这些有版本的资料仅供 M5 使用，不会读取或写入共享的
   Organizations 目录。
2. 明确登记固定 Production，然后另行授权对其当前配置进行本地合成检查。
3. 发送固定的合成研究流程。稳定的运行 ID 可防止在当前工作区重复提交；
   中断的发送不会自动重试。运行会冻结两份已确认的资料。
4. 等待已存储的采集器证据，其采集状态为 `captured`；选择已发布且符合条件的
   Agent 版本，并明确确认模型费用，然后才可授权 **1 review / 2 requests**
   （1 次审查 / 2 个请求）。服务器使用已冻结的资料，无需重新输入业务背景。
5. 查看 Result / Why / Next（结果 / 原因 / 后续步骤）及已保存的 AI 日志。
   状态轮询为只读；待处理、缺失或失败的证据都不代表无风险。旁边的
   **AI log** 按钮无需授权推理即可使用。

只有模型费用同意使用复选框。同意仅适用于该运行、Production 配置、Agent
版本/配置和审查约定；这些标识发生变化或重置演示后，不会继续沿用同意。
不会自动启动审计，页面也不会购买模型重试。如果提交结果不确定，
**Reconcile exact audit submission**（核对确切的审计提交）会明确重新提交原来的
单次授权 ID、固定的 Agent 版本、哈希值和费用确认；不会生成新 ID 或新预算。
即使授权响应丢失，已保存的授权也会阻止再次购买同一份同意。
去重后的会话/正文审查会分别显示其代表性 header 和目标投递 header。
接收方 header 和回执是投递引用，不是已采集监控证据的证明。当前结果会分别显示
采集器状态、观测到的源/目标/会话，以及已存储的最小化字段和日期精度。
只有采集器报告 `captured` 后才允许授权审计。
重置需要输入 `RESET M5 DEMO`：它会归档 M5 范围内的记录，并仅清除演示的逻辑
登记、资料和运行。实际 IRIS 消息和已保存风险报告仍会保留；其他 Productions
及共享资料不受影响。重置不等同于物理删除。

### 已保存的 AI 执行日志

每个模型执行操作旁边都有 **AI log** 按钮：Agent 生成、测试/重测、监控摘要、
独立事件调查、声明审查、发送后比较、Production 审查授权和多组织审计。
打开日志只会读取已保存记录；不会启动、重试或授权推理，不会发送业务数据，
也不会产生模型费用。即使执行操作已禁用，日志仍可使用。

分阶段审计会显示保留的 LLM 响应、模型、时间戳、AI Hub 会话、用量和记录的错误。
请求输入和系统提示词可展开。三个接收方的审计会显示全部三份报告，包括失败阶段。
Production 授权日志会收集该确切授权对应的报告。旧版执行会公开其原始已保存记录；
若只存储了经过验证的结果，则不会将其冒充为原始服务提供方响应。
缺失的执行身份或输出会明确报告，绝不会从会话 ID 或预留请求推断。
SDK 用量不是服务提供方发票。重新打开页面后，生成日志使用明确的已保存作业 ID
选择器；其他旧日志根据持久化的配置/快照/事件/Agent 标识匹配。
历史调查事实会标记为采集时的事实，不会声称它们与事件当前版本一致。

这是范围受限的本地演示，不是生产监控控制台。
**Knowledge 使用真实且经过身份验证的 IRIS API**，提供本地 CPU 嵌入状态、
证据检索和持久化 shadow-index 构建。参阅
[设置、凭据与安全边界](../contest/KNOWLEDGE.md)。
此页面不会调用付费模型或业务 Production。

**Productions**（`/pipelines`）是多 Production 监控工作区：发现可访问的本地
IRIS 命名空间中处于活动状态的 Productions，明确登记选定的 Production/配置，
然后查看其隔离事件、关联的风险审查历史和观测覆盖情况。登记涵盖所有当前组件活动，
无需手动逐条登记业务流程。登记不会编辑业务主机，也不会授予访问载荷/模型的权限。
M2 在后端记录实际边和与会话关联的证据；另行授权的本地检查支持已登记的
FHIR/JSON 消息属性，但观测结果不包含原始消息值。M3 在后端增加单独付费、
抽样式 AI Hub 审查；已保存评估会显示在此页面现有的风险信息流中，并链接到
Production 事件供人工审查。登记和浏览器刷新都不会授予预算或推理权限。
M4 增加实际消息边、按会话筛选的不可变证据、Production 范围的采集/审查处置
和工作进程健康状态。审查详情会将每份报告绑定到其观测记录，并显示经过验证的、
针对具体问题的引用、完整的带日期来源文本、缺失信息问题、SDK 会话和用量。
这些是范围受限的评估，不是合规认证。仅 Builder 可用的控件会分别授权/撤销本地
合成检查和限额 AI 付费。付费前必须显式预览固定命令并最终确认付费；重试沿用同一
不可变预算。可选的高级语义上下文编辑不会成为 Production 观测的门槛，也不会自行
授权检查、推理或重放。Reader 账户可以检查证据，但不能更改授权/上下文。
M5 已登记的合成数据接入还会展示经过验证的本地 SQL 接入、实际接收方/批次、
已冻结的业务策略，以及与范围受限 AI 评估分开显示的消息/会话/摘要绑定。
已保存的 M5 Production 展示常规、本地最小化偏差、业务上下文未知和新观测到的
活动路径案例；其模型授权已撤销。这些特定于适配器的证据，并不能自动得出适用于
每个 Production 的法律结论，也不能证明接收方之后的行为。
演示不要求连接真实医院系统。在 **AI review approval, demo business premises and
bounded funding**（AI 审查批准、演示业务前提和限额付费）中，批准者可以输入
接收方/关系、实际预期目的、所依赖的许可、授权状态及范围、保障措施和特殊条件/例外。
还要说明哪些技术主机代表业务接收方，以及会话消息是否涉及同一合成患者/活动和数据
范围。这些映射是明确由用户提供的前提，不是推断出的身份。在已采集的观测记录上使用
**Use session … for demo approval**（将会话用于演示批准）来选择源会话。
准备批准会将这些输入确立为合成场景前提；单独确认付费审查前，请检查确切的同意内容。
该明确操作仅在**模拟范围内**确立所提供的事实，并不代表经过独立核实的现实情况，
也不是预设的法律判定。未知答案仍保持未知；“不存在”和“不依赖”是不同选项。
其他会话仍会被观测，但不会在此范围授权下使用预算。已完成/失败/跳过的终结审查不会
自动重新评估。服务器会将输入与经过身份验证的批准者/时间及确切的
Production/配置/Agent 约定一起冻结。授权历史和审查详情会将这些输入与观测到的消息
事实分开显示。编辑任何前提都需要准备新的批准；准备好的输入会锁定，直至丢弃。

普通资料/上下文保存、本地检查、监控登记和撤销都通过明确按钮完成，不需要重复确认
复选框。多组织演示使用 **Save for demo**（保存以供演示）、**Prepare demo data**
（准备演示数据）、**Run distribution**（运行分发）和 **Run AI audit**（运行 AI 审计）；
只有模型付费仍保留费用复选框。范围选项（例如包括尚未审查的已存储采集记录）仍可用。
已测试的 Agent 发布和意图绑定同样使用直接按钮，同时保留服务器端测试、版本和权限检查。
本地知识索引构建和仅限目录的批准也使用直接按钮。涉及实际投递/配置变更的重要批准仍
保留确切计划确认。
共享法律审查器还另有一个针对既定事实的八案例前瞻性 Privacy Rule 基准。
这个由助手编写的小型基准并非独立法律验证，也不是对真实部署的认证。

### 数据使用声明（D3）

打开 <http://localhost:5173/declarations>，或在侧栏选择 **Data-use declarations**
（数据使用声明）。这是新的应用工作流，与下方固定路由基线分开，使用真实的
[D1/D2 API](../contest/DECLARATION-WORKFLOW-PLAN.md)。

1. 在工作区入口使用现有账户登录一次。应用内导航时所有页面共享该登录状态；
   凭据保留在 React 内存中，页面切换不会清除，但全局登出或完整刷新会清除。
   本地开发演示可以预填下文所述的忽略环境变量中的凭据；凭据绝不会存储在浏览器存储中。
   Reader 可以查看记录；变更需要 Builder 权限。
2. 选择 **New declaration**（新建声明）。输入你自己的目的、活动、输出、接收方、
   资源/字段、必要性、处理方式、安排和有效期。不会自动选择已批准的 QI 场景。
   已登记的接收方关系和处理能力会单独显示。
3. **Save draft revision**（保存草稿版本）会持久化不可变提案，不会调用模型。
   编辑时使用确切的父版本/摘要固定值，且不能复用原有评估。
4. **Submit for AI review**（提交 AI 审查）会记录审查意图并显示确切的两请求费用计划，
   本身不会调用模型。只有勾选初始为空的授权复选框并选择 **Authorize and queue review**
   （授权并排队审查）才会为任务提供资金。不会自动重试，也不包括业务投递。
5. 已存储的排队/运行中任务状态每四秒刷新一次。这是只读轮询；即使关闭浏览器，
   IRIS 工作进程仍会继续运行。技术失败与风险/无风险/需要信息的结果彼此区分。
6. 检查针对提案的推理、重要问题和可展开的来源摘录。解码器将报告绑定到确切任务、
   来源 Agent、输入和提示词约定，并根据固定来源核验引用原文。展开来源信息可查看实际
   Agent 会话、知识索引、token 和原始阶段输出。缺少的用量标记为未记录，不会伪造为零。
7. 人工可选择 **Return for changes**（退回修改）、**Reject revision**（拒绝版本），
   或仅批准已完成、无风险、当前有效且已提交的版本。每项决定都需要理由和明确的确切版本
   确认；服务器会重新检查所有权限、目录/有效期和任务哈希。AI 给出肯定结果本身绝不会
   自动成为批准。可通过分页历史查看以前的版本。
8. D4 在确切版本下方增加 **Run an approved synthetic batch**（运行已批准的合成批次）。
   选择新的批次 ID，准备投递计划并确认初始未勾选的投递授权。计划绑定声明、任务、
   人工决定和 UTILIZATION 配置。它只会向已登记的内部 SQL 接收方发送现有的
   四资源/七字段、仅年份方案；不包含模型调用或全局路由切换。不支持、过期、时间无效或
   未批准的版本无法运行。
9. 检查关联的执行历史和可展开的 SQL 回读回执。相同提交会返回同一执行记录；
   不确定/失败的任务绝不会自动重放。如果 HTTP 响应丢失，应读取同一批次历史，
   不要换一个 ID 强行重试。回执包含确切的声明/决定/审查哈希、源/输出摘要以及真实
   BS/BP/BO 消息/会话关联。发送后比较与投递成功是分开的。参见下方的自动比较控件。

**D4 现场验收已通过：**明确授权本地重新加载 `UtilizationProcess` 和
`AnalysisReceiver` 后，浏览器确认了 `demo-d3-browser-quality` 版本 2 的新批次
`declaration-quality-d4-002`。它投递了四个资源和七个投影字段；SQL 回读以及确切的
声明/审查/决定关联均通过。其 IRIS 会话为 45，源正文为 33，接收方正文为 34。
两次相同命令提交返回同一执行/回执，最终仅有一条 SQL 行和四个会话 header。
较早的 `declaration-quality-d4-001` 仍为 `reconciliation_required`，SQL 行数为零；
没有重放，也没有重新标记。没有重启整个 Production 或 IRIS，没有全局注册更改，
也没有模型调用。发送后自动比较现在已如下面 D5 所述接通。

### 自动声明批次比较（D5）

每次已投递执行都会显示自己的 **Automatic post-send comparison**
（自动发送后比较）。现有 Production 定时器会启动独立的单工作进程观察器：
浏览器既不会扫描批次，也不会启动模型运行时。它只发现已投递的声明执行，
核验历史来源、投影、消息和 SQL 回执，并冻结与确切声明/审查/人工决定绑定的比较数据包。

自动采集**不会自动授权模型费用**。新批次初始显示 `blocked_budget`，尝试次数为零。
Writer 可以准备确切的回执/证据/Agent/提示词费用计划，并单独确认最多两个请求。
随后后台工作进程会执行真实的两阶段 AI Hub 审查。重复扫描、刷新和相同授权请求都不会
增加推理；失败/中断的模型工作不会自动重试。

页面区分观测到的使用风险、重要问题、已检查使用未发现偏差和技术故障。
可展开引用和原始阶段来源；解释及适用性/条件链来自实际已接受的报告。
请求的目的/保障措施仍属于声明，而观测到的投递、实际输出、项目批准和已登记的合成关系
具有明确的来源信息。即使字段投影匹配，页面也不会声称观测到了之后的目的、转发使用或删除。

记录备注，并按现有事件状态机允许的方式将事件从 `open → in_review → resolved`，
或请求信息/忽略/重新打开。事件操作绑定确切的事件版本，并保留操作者/时间历史。
它们不能更改声明批准、重新发送数据、重试模型，也不能把未付费/失败的审查标记为已完成。

`declaration-quality-d4-002` 的真实验收由 Agent 会话 169/170 完成：
**在已检查的使用中未发现偏差**，没有重要缺口，有两条来源已验证的引用。
浏览器将事件更新为 `resolved` v3，并添加两条备注。只用了 **2 个请求 / 23,568 个 token**。
SQL 仍只有一行，会话 45 仍有四个 header，旧失败批次没有变化。
初始免费采集因事实长度不符合约定而失败；错误保留在 `capture_failures` 和审计记录中，
并在将提案拆分为有界语义事实后明确重新采集。没有把任何模型失败重新标记。

## 使用 Node 运行

使用 Node 22.12+（已用 22.23.3 测试）：

```sh
cd web
npm ci --legacy-peer-deps
npm run dev -- --host 127.0.0.1
```

打开 <http://127.0.0.1:5173>。此 lockfile 是在 npm 10 默认 resolver 因
`edgesOut` 失败后，使用 npm 的 legacy peer resolver 生成的；恢复此 lockfile 时也要使用相同标志。

使用宿主 Node 时，运行
`PLATFORM_API_TARGET=http://127.0.0.1:52779 npm run dev -- --host 127.0.0.1`。
Docker Node 默认使用 `http://host.docker.internal:52779`。两个代理只转发监控 API 路径，
并使用调用方提供、仅驻留内存的凭据。

### 共享工作区登录

包括直接链接在内，应用的所有页面共用一个登录入口。登录后，在 Overview、Instances、
Pipelines、Declarations、Legacy routes、Events、Rules、Agents、Knowledge 和 Runs 之间
使用侧栏导航或浏览器前进/后退时，都会保留同一内存身份。每页会自动加载自己的记录；
页面专属的 Connect/Sign out 表单已移除。侧栏和页眉显示经过身份验证的账户，而非模拟用户。

页眉中的 **Sign out** 会清除共享身份、卸载经过身份验证的页面/确认框，并中止该身份的
进行中请求。HTTP 401 也会使整个工作区返回登录界面；HTTP 403 则作为明确的页面级权限
错误处理，不会清除有效会话。身份验证仍使用现有 IRIS API 及其服务器端 reader/builder
检查；不会更改角色，也不会自动授权模型调用或投递。

凭据/Basic authorization 仅保留在内存中，不会进入 cookie、URL、localStorage 或
sessionStorage。完整刷新浏览器、打开新标签页或重新打开应用都需要重新登录；
这是共享 SPA 身份验证，不是跨应用 SSO 或持久化服务器会话。忽略的
`web/.env.local` 中旧有的 `VITE_DEMO_USERNAME`/`VITE_DEMO_PASSWORD` 设置，
可以仅在 localhost 上的 Vite 开发模式中预填共享登录表单。本地演示使用这些现有设置：
打开应用或登出后会显示预填表单，但仍需单击 **Sign in**。凭据无效时会清除密码，
不会自动重试。源代码没有硬编码密码，生产环境或远程主机名也不会启用预填。
Vite 环境值会暴露给浏览器，不是秘密存储；只能使用一次性本地演示凭据，并在分发构建前删除。
HTTP 演示应保留在 localhost；远程部署前应使用 HTTPS 和适当的会话机制。

## 不使用宿主 Node 运行

从仓库根目录在隔离的 Node 容器中安装已声明的依赖，然后启动仅监听 loopback 的预览：

```sh
docker run --rm -v "$PWD/web:/app" -w /app node:22-alpine \
  npm ci --legacy-peer-deps --no-audit --no-fund
docker compose -f web/compose.yaml up -d
```

这不会启动或重新配置 IRIS。macOS bind mount 使用轮询检测开发更新。只停止此预览：

```sh
docker compose -f web/compose.yaml down
```

不要在宿主 macOS 和 Linux 容器之间共用同一个 `node_modules`：应在实际运行构建的环境中安装。
lockfile 已提交；依赖、构建输出和测试产物均被忽略。
